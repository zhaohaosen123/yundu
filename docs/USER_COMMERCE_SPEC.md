# 用户端与商业化验收规格

## 用户端主流程

1. 注册或通过 OAuth/OIDC 登录，首次登录完成邮箱/手机号和服务条款确认。
2. 在模型目录查看公开别名、上下文能力、输入/输出单价、计量单位、更新时间和状态。
3. 创建 API Key：设置名称、过期时间、额度、模型范围、来源 IP/CIDR 和速率限制；明文只展示一次。
4. 充值：选择金额和支付渠道，订单进入“待支付”；支付回调验签并幂等入账，重复回调不能重复增加余额。
5. 调用 API：预扣余额，成功后按真实用量结算；失败请求按策略释放预扣，余额不足返回统一错误码。
6. 在消费明细中查看模型别名、token/秒数/张数、单价、金额、request ID 和时间，不显示资源池及上游身份。
7. 需要发票时维护抬头/税号/邮箱，提交开票申请并跟踪审核、开具、寄送或电子票状态。

## 管理端主流程

- 模型目录：维护公开别名、能力、价格版本和可见性。
- 资源池：按别名查看渠道、权重、优先级、健康、熔断、成本和近时段指标；密钥默认不可见，查看需要二次认证。
- 账户与订单：查询余额变更、充值订单、退款、发票和异常回调；所有写操作保留审计。
- 风控：配置注册/登录限速、API Key 限额、IP/地域策略、异常消费阈值和人工冻结。
- 运营：配置套餐、赠送额度和阶梯规则；宣传文案必须对应真实权益，不能宣称低于官方价或无限量。

## 支付适配器约束

- 每个渠道实现 `create -> redirect/qr -> webhook -> query -> refund` 生命周期，业务层不依赖供应商 SDK。
- 回调必须校验签名、商户号、金额、币种、订单号和时间窗口；状态转换使用幂等键和数据库事务。
- 支付凭据从 Secret 管理读取；沙箱/生产环境隔离，缺少配置时后台显示“未启用”，不返回堆栈或凭据。

## 发票配置占位

税率、发票类型、开票服务商、抬头字段、金额阈值、开票时限、电子票回传地址均配置化。未配置服务商时允许用户保存抬头并提交申请，但必须明确显示“待人工处理”，不能伪造已开票状态。
