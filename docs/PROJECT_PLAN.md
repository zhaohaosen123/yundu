# AI API 中转站实施路线

## 选型结论

本项目基于 [QuantumNous/new-api](https://github.com/QuantumNous/new-api) 构建（当前核验：约 48k stars、AGPL-3.0）。它已经提供多供应商适配、OpenAI/Claude/Gemini 兼容协议、统一鉴权、用量统计、计费、Redis、SQLite/MySQL/PostgreSQL、OAuth/OIDC、WebAuthn/TOTP 和管理后台，适合作为网关底座。

`songquanpeng/one-api`（约 37k stars、MIT）作为备选参考；它的许可证更宽松，但当前版本的产品化能力和扩展面不如 New API。正式商用前必须保留 AGPL 声明、修改说明和对应源码提供方式，并由法务确认网络交付义务。

## 分阶段交付

### 阶段 0：本机基线（当前）

- 固定上游版本和变更记录，保留可回滚的升级路径。
- 提供 `docker-compose.local.yml` 单容器 SQLite 配置，适合开发体验；生产使用仓库自带的 PostgreSQL + Redis Compose。
- 用 Docker Compose 启动网关、PostgreSQL、Redis。
- 建立环境变量、密钥、日志、备份和健康检查约束。
- 以 SQLite 完成本机快速验证，生产默认 PostgreSQL + Redis。

### 阶段 1：资源池与路由治理

- 每个公开模型建立独立资源池，资源只在后台可见。
- 支持权重、最少连接、延迟优先、错误熔断、冷却和健康探测。
- 请求日志仅记录脱敏后的模型别名、池 ID、耗时和结果；不记录 key、Authorization、完整 prompt 或响应体。
- 上游模型名通过模型别名映射隔离，错误信息统一化，避免暴露供应商和真实部署。

### 阶段 2：用户端与商业化

- 注册/登录：密码 + OAuth/OIDC + 可选 Passkey/TOTP；敏感操作强制二次认证。
- 账户：余额、充值订单、消费明细、API Key 生命周期、额度/限速、模型价格目录。
- API Key：只显示一次明文，数据库仅保存哈希；支持撤销、轮换、过期和来源限制。
- 订单：支付渠道采用适配器，先接沙箱；回调验签、幂等、对账和退款状态机独立实现。
- 发票：开票信息、抬头/税号校验、开票申请与状态留痕，具体税务规则做成配置。

### 阶段 3：安全与运维

- 管理员 RBAC、最小权限、登录风控、CSRF/Origin 校验、限流、WAF/反代和安全响应头。
- 密钥使用外部 Secret 管理或 Docker secrets；生产禁止默认密码和明文日志。
- 数据库每日备份、恢复演练、审计留存策略、告警和指标（成功率、P95、余额异常、熔断次数）。
- 供应商密钥按池隔离，支持轮换；出站网络仅允许配置的上游域名。

### 阶段 4：上线前验收

- OpenAI Chat/Responses、Claude、Gemini 兼容接口各完成成功、鉴权失败、限额、超时、流式和重试验证。
- SQLite、PostgreSQL、MySQL 完成迁移与回归矩阵；支付和 OAuth 使用沙箱或本地替身验证。
- 完成渗透测试、依赖漏洞扫描、灾备恢复演练和 AGPL 合规审查。

## 当前非目标

本阶段不接入真实支付、不写入真实供应商密钥、不承诺具体模型可用性或监管合规。所有供应商、价格、税率、登录和支付参数均从配置读取，并在缺失时明确提示管理员。
